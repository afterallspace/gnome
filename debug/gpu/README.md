## Симптом

INSIDE, 4K, Steam + Proton. FPS падает с 55-60 до 17 и держится на минимуме,
плюс жёсткий инпут-лаг. Падение через 2-3 секунды после запуска игры.
Переустановка ОС помогает ровно на один вечер. То же было на CachyOS +
Hyprland (там деградация заняла ~2 месяца).

## Что установлено точно

**Видеокарта душится до ~16 Вт вместо положенных 35** при полной загрузке.
Это не тепло (53 °C при пороге 97), не нехватка питания (PSYS 43 Вт при
лимите 56, CPU 14 Вт при лимите 52), не память, не шина, не композитор.
Флаг троттлинга всегда `0x4 SwPowerCap` — **программный** потолок, который
драйвер назначил себе сам. Аппаратных срезов (`0x8`, `0x100`) не было ни разу.

При этом `enforced.power.limit` рапортует 35.00 Вт. Реальный потолок не
виден ни в одном доступном поле — он живёт в прошивке GSP.

**Состояние фиксируется при загрузке** и внутри сессии не меняется ничем:
ни батареей, ни остановкой демонов, ни RTD3, ни PowerMizer. Помогает только
перезагрузка — и то примерно в 8 % случаев.

**Корень — в прошивке.** На каждой загрузке:

```
NVRM: GPU0 ... PlatformRequestHandler failed to get target temp from SBIOS
NVRM: GPU0 ... PlatformRequestHandler failed to get platform power mode from SBIOS
      [NV_ERR_INVALID_DATA] (0x00000025)
nvidia-powerd: DC power limits table is not supported
nvidia-powerd: Client (presumably SBIOS) has requested to disable Dynamic Boost DC controller
```

Канал согласования «платформа ↔ видеокарта» не работает. Но эти же ошибки
были и в хорошей сессии — значит они необходимое условие, а не спусковой
крючок. Что дёргает крючок, не найдено.

## Главная проблема расследования

**Хорошая загрузка выпадает примерно в 8 % случаев** (2 из ~15). При такой
базе одиночная проверка не доказывает ничего: вероятность увидеть хорошую
загрузку за 4 попытки даже при бесполезном вмешательстве — около 28 %.

Поэтому выводы делятся на два сорта:

- **Надёжные** — полученные *внутри одной сессии*, сравнением до/после в
  одинаковых условиях: остановка `nvidia-powerd`, смена состояния батареи на
  лету, RTD3, PowerMizer, память, лимиты CPU.
- **Слабые** — потребовавшие перезагрузки и оценённые по 1-4 загрузкам:
  WMI-драйвер, порядок DRM, `kms`, зарядка в момент загрузки. Формально
  «не помогло», статистически — «не отличили от невезения».

Чтобы отличить 8 % от 50 %, нужно 25-35 загрузок на вмешательство.

## Инструменты

| Скрипт | Назначение |
|---|---|
| `./bootcheck.sh` | **главный**. Хорошая эта загрузка или плохая, ~25 с. С 15.08 ничего не записывает — чистая диагностика |
| `./powercheck.sh [сек]` | тракт питания: PD-контракт, износ батареи. С воткнутым адаптером |
| `./precheck.sh` | память и VRAM перед игрой |
| `archive/monitor.sh` и др. | инструменты закрытого наблюдения (телеметрия, дифф загрузок) |

Зависимости: `sudo pacman -S --needed mangohud lib32-mangohud glmark2`

### Как пользоваться

```fish
# после обновления драйвера/BIOS — вердикт за 25 секунд
cd ~/.config/debug/gpu && ./bootcheck.sh
```

Порог: **~16 Вт — плохо, 30+ — хорошо.** Между ними широкий зазор.

## ⚠ Грабли этой машины

Каждая стоила часов. Проверено, не повторять:

1. **`modprobe.d` для nvidia НЕ работает.** Модуль грузится из initramfs
   (хук `kms`), конфиг до него не доходит. Параметры задавать только через
   командную строку ядра: `LINUX_OPTIONS` в `/etc/sdboot-manage.conf`, затем
   `sudo sdboot-manage gen`.
2. **`/sys/module/nvidia/parameters/` пуст.** Проверять применение параметров
   только через `/proc/driver/nvidia/params`.
3. **`vkmark` не годится для замера.** Рисует в окно, упирается в
   вертикальную синхронизацию 60 Гц, выдаёт максимум ~11 Вт при любой сцене —
   не достаёт даже до потолка в 16 Вт. Использовать
   `prime-run glmark2 --off-screen`.
4. **`-p immediate` у vkmark не поддерживается картой** — падает мгновенно.
5. **`nvidia-smi -pl` заблокирован в vBIOS** — `not supported in current scope`.
5а. **`nvidia-smi` БУДИТ карту из D3cold — простой им не измерить.** С
   включённым RTD3 карта обесточена, драйвер обязан поднять её ради опроса,
   и она выходит в `P0`. Полученные ~10 Вт — мощность пробуждения, а не
   простоя; при отключённом RTD3 та же команда честно показывала 5 Вт в
   `P8`, потому что будить было нечего. Родственник грабли №8: измерение
   разрушает измеряемое. Простой смотреть **только через sysfs**, они
   карту не трогают:
   ```fish
   cat /sys/bus/pci/devices/0000:01:00.0/power_state          # D3cold / D0
   cat /sys/bus/pci/devices/0000:01:00.0/power/runtime_status # suspended / active
   cat /sys/bus/pci/devices/0000:01:00.0/power/runtime_suspended_time
   ```
   Доля сна считается приростом `runtime_suspended_time` за интервал. Чистый
   замер 03.08 дал 60006 мс сна за 60004 мс реального времени — 100 %.
6. **`dmesg` закрыт** (`dmesg_restrict=1`), использовать `journalctl -k`.
7. **Журнал вычищается за часы.** Лог хорошей загрузки 12:57 был потерян через
   три часа. Поднять лимиты:
   ```fish
   sudo mkdir -p /etc/systemd/journald.conf.d
   printf '[Journal]\nSystemMaxUse=2G\nMaxRetentionSec=1month\n' | \
     sudo tee /etc/systemd/journald.conf.d/keep-more.conf
   sudo systemctl restart systemd-journald
   ```
8. **Не сворачивать игру перед `nvidia-smi`** — она встаёт на паузу, GPU
   уходит в P5, и получается склейка несовместимых снимков. Один раз это
   увело расследование на полдня.

## Что осталось непроверенным

1. **Ветка драйвера 580** — последняя с поддержкой Ampere, есть в репах
   (`nvidia-580xx-open-dkms`, `nvidia-580xx-dkms`). Проприетарный вариант
   умеет работать без GSP (`NVreg_EnableGpuFirmware=0`), открытый — нет.
   Осмысленно только со статистикой по многим загрузкам.
2. **Обновление BIOS от Xiaomi** — корень в SBIOS, отдающем мусор.
3. **Баг-репорт в NVIDIA.** Материала достаточно: парные замеры, эталон,
   `bootlog.csv`, снимки, таблица закрытых версий.
4. **Автоматизация перебора загрузок** — systemd-сервис, гоняющий
   `bootcheck.sh` при каждом старте и перезагружающийся дальше до первой
   удачной. Единственный способ получить статистику вручную нереального
   объёма. Не реализовано, требует решения владельца — это перезагрузки
   в цикле.
