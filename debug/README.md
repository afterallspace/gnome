# Дебаг системы — Xiaomi Book Pro 16 2022 / CachyOS

Общий каталог расследований по этой машине. Одна ветка — один подкаталог со
своей документацией, инструментами и логами.

Железо и общая беда: Xiaomi не сделали вменяемые таблицы ACPI, BIOS
`XMAAD6B0P1717` от **13.12.2022** ни разу не обновлялся. Отсюда растёт
большая часть здешних проблем — питание, UCSI, отсутствующие интерфейсы.

## Соглашения

Заведены не из любви к порядку, а потому что каждое нарушение здесь уже
стоило часов.

1. **Вся история остаётся.** Отрицательный результат и закрытая гипотеза —
   такой же материал, как удачный. Файлы `.md` не чистим.
2. **Каждая ветка ведёт свой лог** в CSV: `gpu/bootlog.csv`,
   `battery/batlog.csv`, `nvme/nvmelog.csv`. Один запуск инструмента — одна
   строка. Тренд важнее одиночного замера.
3. **Замер обязан отличать «ноль» от «не смог прочитать».** Молчаливая
   подстановка нуля здесь уже один раз выдала ложный вывод
   (см. журнал замеров в [nvme/NVME.md](nvme/NVME.md)).
4. **Выводы делятся на надёжные и слабые.** Надёжные — полученные внутри
   одной сессии сравнением до/после. Слабые — потребовавшие перезагрузки:
   хорошая загрузка выпадает примерно в 8% случаев, поэтому одиночная
   проверка не доказывает ничего. Помечать прямо в тексте.
5. **Тупики держим в `archive/`** с объяснением, почему тупик.

## Грабли этой машины

Полный список — в [gpu/README.md](gpu/README.md), здесь только те, что
кусают за пределами GPU-ветки:

- **`modprobe.d` не работает** для модулей из initramfs (nvidia, nvme_core).
  Параметры задавать только через командную строку ядра: `LINUX_OPTIONS` в
  `/etc/sdboot-manage.conf`, затем `sudo sdboot-manage gen`.
- **`dmesg` закрыт** (`dmesg_restrict=1`) — использовать `journalctl -k`.
- **Журнал вычищается за часы**, если не подняты лимиты (рецепт в
  `gpu/README.md`).
- **`sudo` протухает за 900 с** — длинные замеры должны подогревать кэш
  сами, иначе половина данных потеряется молча.
