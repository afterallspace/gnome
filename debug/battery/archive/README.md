# Архив battery-ветки

В отличие от [`../../gpu/archive/`](../../gpu/archive/README.md), здесь лежат
**не недостоверные данные**. Инструмент рабочий, а выводы, полученные им,
годятся и внесены в [`../BATTERY.md`](../BATTERY.md). В архиве он потому, что
путь закрыт, а не потому, что ошибочен.

## `chargelimit.sh`

Управление порогом заряда через MIFS WMI (`\_SB.PC00.WMID.WMAA`) и, главное,
диагностика этого интерфейса. Написан 05.08.2026, им же ветка и закрыта.

**Почему тупик:** обработчик SMI в BIOS `XMAAD6B0P1717` принимает вызов, но
не реализует группу команд `0x10` (защита заряда). Доказано цепочкой: метод
вызывается → запись в общую память доходит (`CTID`/`MTID` читаются обратно)
→ SMI генерируется (`MSR 0x34` даёт +1 на вызов при нулевом фоне) → ответ не
пишется никогда. Полный разбор — в `../BATTERY.md`, раздел «Лимит заряда:
расследование закрыто».

**Почему стоит хранить:**

- Это готовая перепроверка, если Xiaomi всё-таки выпустит новый BIOS.
  `diag` и `smi` дают вердикт за пару минут вместо повторного реверса
  протокола.
- В шапке скрипта записан расшифрованный протокол MIFS целиком: раскладка
  32-байтового буфера, коды операций, под-функции группы `0x10`, таблица
  кодов порога. Это единственное место в репозитории, где он есть.
- `smi` — универсальный приём для этой машины: показывает, доходит ли
  вообще запись в порт `0xB2` до SMM. Пригодится в любом будущем
  расследовании по ACPI на TM2121.

**Подкоманды** (все, кроме `set`/`off`, только читают):

| Команда | Что делает |
|---|---|
| `status` | порог, здоровье по прошивке, ватты адаптера |
| `diag` | жив ли транспорт: `MTID`, `CTID`, `PSSP`, буфер |
| `smi` | считает SMI через `MSR 0x34` до/после вызова, с фоном |
| `mem` | что реально ложится в память (нужен `/dev/mem`, сейчас не пускает) |
| `rotsweep` | свип предкомпенсации перекоса по всем 32 позициям |
| `calib` | сверка раскладки ответа с эталоном из `hwmon` |
| `probe` | свип функций прошивки `0x01`…`0x30` |
| `raw` | один вызов, сырые байты |
| `set <%>` / `off` | запись порога — **на этой прошивке не сработает** |

⚠ Скрипт требует root и модуль `acpi_call`. Падает с ошибкой вместо
подстановки нуля — по правилу ветки о молчаливых нулях.
